# 데이터셋 준비 도구

천장 카메라 설치 → 캘리브레이션 → 촬영 → 학습까지의 작업 순서와 도구.

---

## 0. 카메라 고정 (먼저 할 것)

**여기서 정한 위치가 시연 때까지 유지돼야 합니다.** 카메라가 움직이면 캘리브레이션 값도, 데이터셋도 다시 만들어야 합니다.

확인할 것:
- 바닥판 1200×1200mm 전체가 화면에 들어오는가
- 네 모서리가 모두 보이는가 (캘리브레이션에 필요)
- 브래킷·삼각대가 흔들리지 않는가
- 시연 때와 같은 조명인가

---

## 1. 캘리브레이션

바닥판 네 모서리의 화면상 픽셀 좌표를 측정합니다. 이 값이 있어야 픽셀 → 실좌표(mm) 변환이 실제 설치 상태에 맞습니다.

```bash
python tools/calibrate_camera.py --camera 0
```

**클릭 순서: 좌상 → 우상 → 우하 → 좌하** (좌하단이 맵 원점 `(0,0)`)

| 키 | 동작 |
|---|---|
| 좌클릭 | 모서리 지정 / (4점 후) 검증점 확인 |
| `u` | 마지막 점 취소 |
| `r` | 전부 지우고 다시 |
| `g` | 100mm 격자 오버레이 켜기·끄기 |
| `s` | 저장 후 종료 |
| `q` | 저장 없이 종료 |

네 점을 다 찍으면 **검증 모드**로 넘어갑니다. 슬롯 중심처럼 좌표를 아는 지점을 클릭해 표시되는 mm 값이 실측과 맞는지 확인하세요.

| 슬롯 | 기대 좌표 (mm) |
|---|---|
| A1 | (425, 1050) |
| A4 | (1100, 1050) |
| B1 | (425, 150) |
| B4 | (1100, 150) |

격자(`g`)를 켜서 주차선과 격자가 나란한지 보면 왜곡·기울어짐을 눈으로 잡을 수 있습니다.

출력된 값을 `pipeline/config.py` 의 `PipelineConfig` 기본값에 넣거나, 실행 시 인자로 넘깁니다:

```python
PipelineConfig(
    homography_src=[(x1, y1), (x2, y2), (x3, y3), (x4, y4)],
    lot_width_mm=1200.0, lot_height_mm=1200.0,
)
```

## 2. 촬영

카메라가 고정이므로 **차량이 움직여서** 다양성을 만들어야 합니다. 영상 3~5개로 나눠 찍고 프레임을 뽑습니다.

| 구성 | 목표 | 이유 |
|---|---|---|
| heading 8방향 (0/45/90/…/315°) | 100장 | 쿠션 방향 학습의 핵심. 제자리 회전 |
| 화면 내 위치 (중앙·네 모서리·가장자리) | 70장 | 가장자리는 렌즈 왜곡이 크다 |
| 주행 상황 (입구·통로·슬롯 진입·주차 완료) | 60장 | 실제 운용 구간 |
| 조명 (기본·그림자 걸침·밝음) | 40장 | 시연장 조명 변동 대비 |
| 일부 가림 (주차선 걸침, 화면 잘림) | 30장 | 보이는 부분만 박스 |

**총 ~300장.**

정지 장면을 충분히 넣으세요. 쿠션의 존재 이유가 "정지 중 heading" 이라, 정지 데이터가 없으면 정작 필요할 때 약해집니다.

---

## 3. 프레임 추출

```bash
python tools/extract_frames.py videos/*.mov -o frames/ --total 300
```

영상을 목표 장수만큼의 구간으로 나누고, 각 구간에서 **가장 선명한** 프레임을 하나씩 고릅니다. 시간 분포를 유지하면서 모션 블러를 피하고, 항상 목표 장수를 채웁니다.

- `--per-video N` 영상당 N장
- `--candidates N` 구간당 비교 후보 수 (기본 3, 늘리면 더 선명하지만 느림)

## 4. 사전 라벨링 (선택, 시간 절약)

차량 박스는 기존 가중치로 미리 뽑아두고, 사람은 검수와 쿠션 추가만 합니다.

```bash
python tools/preannotate.py frames/ --weights best05.pt --review
```

- `--conf 0.3` 낮게 잡고 검수에서 지우는 편이 낫습니다 (놓친 것보다 지우는 게 쉬움)
- `--review` 박스가 그려진 확인용 이미지를 `frames/_review/` 에 저장

**자동 라벨은 완벽하지 않습니다.** 탐지 0건·2개 이상인 파일을 따로 알려주니 그것부터 확인하세요.

---

## 5. 라벨링 (Roboflow)

1. 이미지와 `.txt` 를 함께 업로드 → 박스가 미리 그려진 채로 열립니다
2. 차량 박스 검수 — 놓친 것 추가, 헐거운 것 조정, 오탐 삭제
3. **FRONT_CUSHION 을 수동 추가** (클래스 1)
4. 70/20/10 split → YOLO 포맷 export

클래스 이름은 자유롭게 지어도 됩니다. `RC_CAR` / `rc-car` / `Front Cushion` 모두 인식합니다 (`cv/vehicle_detector.py` 의 `_LABEL_ALIASES`).

---

## 6. 학습

```bash
yolo detect train \
  model=yolo26n.pt \
  data=data.yaml \
  epochs=50 \
  imgsz=960 \
  batch=8 \
  patience=10 \
  name=rc_car_v3
```

**`imgsz` 를 640 이 아니라 960 이상으로** 두세요. 파이프라인이 추론을 1280 으로 하는데 학습이 640 이면 스케일이 어긋나고, 특히 **쿠션은 작은 객체**라 저해상도 학습에서 잘 잡히지 않습니다. GPU 메모리에 맞춰 `batch` 를 조절합니다.

---

## 7. 검증

mAP 만 보면 안 됩니다. 이전에 mAP 0.995 가 나왔는데도 실환경에서 confidence 0.7 을 넘지 못한 적이 있습니다. 실제로 파이프라인에 꽂아서 확인하세요.

```bash
python manage.py run_pipeline --camera 0 --weights runs/detect/rc_car_v3/weights/best.pt --show
```

확인할 것:
- 차량과 쿠션이 **둘 다** 잡히는가 (쿠션 confidence 가 특히 중요)
- 쿠션이 올바른 차량에 붙는가 (`cv/association.py`)
- **정지 상태에서 heading 이 나오는가** — 쿠션 도입의 목적
- 계산된 heading 이 실제 차량 방향과 맞는가
- 캘리브레이션 좌표가 실측과 맞는가

## 참고

- 데이터셋은 **증분으로 쌓을 수 있습니다.** 2호기가 나오면 2대 동시 장면(근접·교차)만 추가 촬영해 보강하면 됩니다.
- 카메라를 옮겼다면 **1번부터 다시** 해야 합니다.
