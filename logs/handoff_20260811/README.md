# 자동주행 실차 로그 — 2026-08-11 새벽 (SW팀)

Approach WP / 자동주차 제어 구현에 쓸 수 있도록 시간순 로그 2건을 정리했습니다.

| 파일 | 케이스 | 표본 | 비고 |
|---|---|---|---|
| `case_A_success_10hz.csv` | **성공** — 33.0cm → 9.8cm 도달 | **10Hz 실측** | 전 항목 포함 (엔코더 포함) |
| `case_B_overshoot_0p5s.csv` | **실패** — WP 를 지나쳐 바깥으로 이탈 | 0.5s 콘솔 기록 | pose 원좌표·엔코더 없음 |

> **케이스 B 는 CSV 로거를 붙이기 전 주행이라 콘솔 출력에서 재구성했습니다.**
> 거리·heading·throttle·steering 은 실제 출력값 그대로이고, `servo_deg_calc` /
> `motor_pwm_calc` 는 펌웨어 매핑으로 계산했습니다. pose 원좌표와 엔코더는
> 남아 있지 않습니다. 필요하시면 같은 조건으로 재현해 10Hz 로 다시 뜨겠습니다.

## 컬럼

| 컬럼 | 설명 |
|---|---|
| `wall_time`, `t_s` | 벽시계 시각 / 주행 시작 기준 경과초 |
| `target_x_mm`, `target_y_mm` | 목표 waypoint (바닥판 좌하단 원점, +x 우, +y 상) |
| `cam_x_mm`, `cam_y_mm`, `heading_deg`, `heading_source` | 카메라 pose. heading 은 우 0° / 상 90°, 반시계 양수 |
| `dist_err_cm` | 목표까지 거리 |
| `heading_err_deg` | (목표 방위 − 현재 heading), −180~180 |
| `cmd_throttle`, `cmd_steering` | **노트북이 보낸 값** (wire, 조향 음수=좌) |
| `applied_throttle`, `applied_steering` | **차량이 STATUS 로 보고한 적용값** |
| `servo_deg_calc`, `motor_pwm_calc` | 아래 주의 참고 (**계산값**) |
| `encoder_count` | 차량 STATUS 의 엔코더 누적 카운트 |
| `state`, `mode`, `control_seq` | 차량 상태 / 제어 모드 / DIRECT_CONTROL seq |

### ⚠️ PWM·서보각은 계산값입니다

REMOTE_DIRECT STATUS 에는 `motor_pwm` 과 `servo_angle_deg` 가 실리지 않습니다
(펌웨어 512바이트 상한 때문에 제외, `vehicle_control.c` 주석에 명시). 그래서
`actuator.c` 의 `steering_to_angle()` / `throttle_to_duty()` 를 그대로 재현해
계산했고 컬럼명에 `_calc` 를 붙였습니다.

실측 시리얼 로그(`mock apply thr=0.300 str=0.000 -> pwm=19`)와 대조해 일치를
확인했습니다. **STATUS 에 두 값을 넣어주시면** 계산이 아닌 실측으로 바꾸겠습니다.

## 적용한 제어 파라미터

두 케이스 모두 동일 계열입니다.

| 파라미터 | 값 | 의미 |
|---|---|---|
| `steer_kp` | 1.6 | heading 오차(rad) → 조향 |
| `steer_kd` | 0.25 | 오차 변화율 감쇠 |
| `steer_normalize_deg` | **20** | PD 출력을 −1~1 로 나누는 분모 |
| `max_wire_steering` | 1.0 | 조향 상한 (제한 없음) |
| `wire_steering_sign` | −1.0 | **음수 = 좌회전** (실물 확인) |
| `min_move_throttle` | 0.22 | throttle 하한 |
| `max_throttle` | 0.25 | 실제로는 하한 0.22 에 걸려 무의미 |
| `slow_radius_cm` | 25 | 접근 감속 시작 거리 |
| `stop_distance_cm` | 3.0 | 제동 여유 |
| `position_tolerance_cm` | 8.0 | 도착 허용오차 |
| `speed_cm_s` (waypoint) | 8.0 | 목표 속도 |

**포화 오차 = `steer_normalize / steer_kp` = 20 / 1.6 = 12.5°**
heading 오차가 12.5° 를 넘으면 조향이 ±1.0 으로 포화합니다.

펌웨어 측(`app_config.h`) — **케이스마다 다릅니다.** `_calc` 컬럼은 각 케이스가
실제로 돌던 시점의 상수로 계산했습니다.

| | 케이스 A (23:35) | 케이스 B (11:54) |
|---|---|---|
| SERVO | 50 / 68 / 86 / 104 / 122 (±36°) | 50 / 68 / 86 / 104 / 122 (±36°) |
| PWM 직진 | 12 / 24 | 15 / 27 |
| PWM 약회전 | 32 / 42 | 35 / 45 |
| PWM 강회전 | 52 | 55 |

> 이후 서보를 ±40°(46~126), PWM 을 12/22·32/40·50 으로 조정해 재측정했지만
> **선회 반경은 줄지 않았습니다** (아래 참조).

## 케이스 A — 성공 (23:35:21 ~ 23:35:23)

```
목표 (141, 516)mm
거리   33.0 → 9.8cm      (2.20초)
heading 오차  −9.4° → +3.2°   수렴
조향   +0.75 → −0.19       포화 없음, 부드럽게 감소
엔코더 0 → 1105
```

heading 오차가 12.5° 미만이라 **조향이 포화되지 않았고**, 그래서 깔끔하게
수렴했습니다. 최종 9.8cm 에서 `ARRIVED`(허용 8cm + 제동여유 3cm = 11cm).

### 엔코더 환산 (이 로그에서 산출)

| 항목 | 값 |
|---|---|
| 카메라 기준 주행 경로장 | 23.3 cm |
| 엔코더 증가량 | 1105 count |
| **환산** | **47.4 count/cm** → 1 count ≈ **0.211 mm** |
| 평균 속도 | 10.6 cm/s |

직선 주행 1건에서 뽑은 값이라 참고용입니다. 회전 구간·후진 포함해 몇 번 더
재면 정밀도가 올라갑니다. 기어비·PPR 이 확정되면 이 값과 대조해 주세요.

## 케이스 B — 실패 (WP 지나침 / 궤도 이탈)

```
목표 (339, 579)mm
거리   23.2 → 18.4 → 13.5 → 14.1 → 21.6 → 30.2 → 53.8cm
heading  89° → 86° → 77° → 63° → 49° → 36° → 9°
조향   +1.000 내내 포화 → 마지막에 −1.000 으로 반전
```

**13.5cm 까지 접근했다가 다시 멀어져 목표를 잡지 못했습니다.**

원인은 제어 게인이 아니라 **최소 선회 반경**입니다.

- 최대 조향으로 도는 동안 실측 선회 반경 **~57cm**
- 목표가 측면 13cm 거리에 있으면, 반경 57cm 원으로는 접근이 불가능합니다
- 차는 목표 주위를 돌며 바깥으로 밀려납니다

마지막 행에서 조향이 `+1.0 → −1.0` 으로 뒤집힌 것은 목표가 차량 반대편으로
넘어갔기 때문입니다(제어기 오작동 아님).

## Approach WP 설계 시 반영할 값

| 항목 | 실측 | 설계 반영 |
|---|---|---|
| **최소 선회 반경** | **~57cm** | WP 간 방향 전환이 이 반경 안에 들어가야 함 |
| 도착 정확도 | 9.7~10.9cm | 허용오차를 이보다 크게 |
| 주행 속도 | 10~19 cm/s | |
| 조향 포화 오차 | 12.5° (`nz=20` 기준) | 이 이상 틀어지면 풀 조향 |
| 엔코더 | 47.4 count/cm | 거리 추정에 활용 가능 |

### 제약 두 가지

**1. 선회 반경 57cm 는 소프트웨어로 못 줄입니다.**
서보 운용각을 ±36° → ±40° 로 11% 넓혔는데 반경이 그대로였습니다. 역산하면
실제 바퀴각은 **14~17°** 로, 링키지가 이미 한계입니다. 바닥판이 120×120cm 라
선회 지름(114cm)이 맵 한 변과 같습니다.

→ **Approach WP 는 큰 반경을 전제로 설계**하거나, **후진 기동**을 넣어야 합니다.
현재 제어기는 전진 전용입니다.

**2. 회전 중 속도를 노트북이 제어할 수 없습니다.**
`throttle_to_duty()` 가 `|steering| > 0.5` 에서 duty 를 강회전 기본값으로
올리고 throttle 을 무시합니다. `max_throttle` 을 0.25 → 0.6 으로 올려도 전
구간 `thr 0.22` 로 동일했고 속도도 같았습니다.

→ 회전 감속을 설계에 넣으려면 펌웨어가 throttle 을 선형으로 받아야 합니다.

## 재현 방법

```bash
python tools/single_waypoint_test.py \
    --weights best.pt --camera 0 --calibration calibration.json \
    --max-throttle 0.25 --steer-normalize 20 \
    --log logs/run.csv
```

화면을 클릭해 목표를 지정하면 그 지점으로 주행합니다. 필요하신 조건(파라미터·
목표 배치)을 알려주시면 그대로 재현해 10Hz 로그를 다시 뜨겠습니다.
